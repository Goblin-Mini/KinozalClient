# Отдельная админ-панель Кинозал ТВ Plus

## Архитектура

- **Cloudflare Worker** остаётся закрытым API лицензий и синхронизации.
- **Cloudflare D1** остаётся базой лицензий, устройств и синхронизируемых записей.
- **Cloudflare Pages** размещает отдельный статический сайт администратора из каталога \`admin-panel/\`.
- Страница вызывает API Worker с Bearer-токеном администратора. Сам токен не сохраняется в браузере.

## Что уже реализовано

- Сводка из базы: всего лицензий, активных лицензий, активных устройств и свободных слотов.
- Выдача бессрочного Plus после ручной проверки платежа.
- Лимит устройств на одну лицензию: от 1 до 10.
- Срок действия кода активации: от 7 до 365 дней.
- Поиск и фильтр лицензий.
- Просмотр устройств, отзыв одного устройства и отзыв всей лицензии.
- Код активации отображается только один раз после выпуска.

Платёжный шлюз и журнал платежей пока не подключены. Панель не создаёт вымышленных транзакций и не показывает платёж как подтверждённый без реальной интеграции.

## Развёртывание в Cloudflare через браузер

1. Сначала обновить Worker исходником \`license-server/src/index.ts\` из этого репозитория. В Worker должны остаться существующее D1 binding \`DB\` и secret \`ADMIN_TOKEN\`.
2. В **Workers & Pages → Create application → Pages → Connect to Git** выбрать репозиторий \`Goblin-Mini/KinozalClient\`, ветку \`main\`.
3. Build command оставить пустой; Build output directory указать \`admin-panel\`; root directory оставить пустым (корень репозитория).
4. Назвать Pages-проект, например, \`kinozal-tv-plus-admin\`, и развернуть сайт.
5. Скопировать выданный Cloudflare адрес вида \`https://kinozal-tv-plus-admin.pages.dev\`.
6. В существующем Worker открыть **Settings → Variables and Secrets** и добавить текстовую переменную \`ALLOWED_ORIGIN\` с точным origin Pages, без пути и без завершающего слеша.
7. Сохранить и развернуть Worker.
8. Открыть Pages-сайт, ввести URL Worker и \`ADMIN_TOKEN\`. После успешного входа секрет остаётся только в памяти текущей вкладки.

## Безопасность

- Не публиковать \`ADMIN_TOKEN\` в GitHub, APK, исходном коде страницы, URL или сообщениях.
- Не включать wildcard CORS. Worker разрешает только точный \`ALLOWED_ORIGIN\`.
- Не удалять и не пересоздавать D1, binding \`DB\` или секрет \`ADMIN_TOKEN\` при развёртывании панели.
- После работы нажать «Выйти» и закрыть вкладку администратора.
